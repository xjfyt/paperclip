## 优先级与原计划/建议分界

1. 先推进剩余实际路径i18n与IME/布局验收；通知三类coding事件的有界摘要已实现，其余事件范围仍单列；AUTH-06 退出提示和通知配置等级已实现，后续侧重对应实测；各切片需自己的类型/定向回归，最终 SHA 再验。
2. 后续原计划闭环：P3 已有来源关联与人工历史回执，仍需真实复现/修复效果；P4 实际来源+routines、月度业务读取/写入/对账；P5 首期应用/回退与成本路由的最终回归、真实CLI验收及范围外profile；P2 可信 Runner/签名采集和上传。涉及合同的部分先约定合同，不造业务 API。
3. 外部输入单列：Casdoor/Qoder/WorkBuddy/通知/GitLab 真实账号与允许目标，构建机/签名/上传和业务数据合同；取得前保持 C3/C4 blocked，不把代码缺口全部归因为缺账号。
4. **可选实现方案而非原文硬要求**：语义模型聚类、自动复现、自建公共 GitHub releases collector、能力证据全自动核验。确定性分组、人工可核验复现和已有 Agent/routines 获取来源可满足相应有界要求；仍须实际证据，不能仅有占位状态。
5. 用户后续新增的“可跳过 Agent 的初始化入口”属于扩展交付，已另有历史验收，不把它冒充原计划条目或据此宣布原计划完成。八小时排程、持续改进是过程/观察要求，不用固定完成百分比。
