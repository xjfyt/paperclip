# 受控成本路由 v2 验收清单

日期：2026-10-27。当前为待集成验收清单；具体自动化通过结果以 [VERIFICATION](../VERIFICATION.md) 的相应提交记录为准。旧 v1 预览仍只读且阻断，不作为运行授权。

## 安装与数据安全

- 升级前保持 `PAPERCLIP_RUNTIME_COST_ROUTING_ENABLED` 未设置或为 `false`，停止应用/worker 写入，在维护窗口备份并确认可恢复。
- 0359 在现有唤醒表创建唯一索引，不是在线 DDL；5 秒锁等待与 120 秒语句超时不保证零停机。失败后检查事务与迁移历史，不删除证据或禁用约束强行升级。
- 使用独立测试库，检查旧库升级及新库完整迁移、重复启动无重复迁移。不要在生产库运行破坏性夹具。
- 开启开关不自动批准策略、创建任务或调用模型。真实账号、费用、通知、发布和合并须另行明确授权。

## 配置、证据与四语言

- 中英西日切换后标签、确认项与状态正确；模型 ID、用户原文、候选 ID 不翻译、不改写。
- 页面刷新、切换公司/账号及重新登录后只恢复当前有权读取的元数据；旧账号延迟响应不能覆盖新状态。
- 每个候选必须有其自身 Agent、模型、供应商与完整固定集证据，且对应已批准的提示词应用代次；不能借用其他候选费用。
- 缺失、重复、过旧、未来时间、来源不符或版本/配置漂移应拒绝。未知费用不是零费用。
- 明确显示历史 CLI 费用并非供应商账单或未来报价；`bare_text_proxy_v1 / exact_text_v1` 不证明普通工具任务质量，不代表完整执行上下文。
- 首版仅支持固定公司 API-key 的内置 Claude 本地适配器和新建、无项目/父任务/旧会话的任务；其他适配器、remote、resume、retry、额外包装不默默降级。

## 人工确认与一次执行

- 准备、批准策略不创建任务、不唤醒执行；同一请求重复提交不增加审计或代次。
- 创建前审阅真实任务标题、正文并明确确认公司可见；创建成功后仍不自动运行。
- 运行另行明确确认执行与可能收费；在独立无网络 Node 替身夹具中检查重复点击、响应丢失和并发请求只生成一个绑定运行。
- 通用唤醒、评论、重新分配和重试入口不能绕过受控绑定；预算、权限、公司暂停、当前代次和配置漂移仍须在执行前检查。
- `start_requested` 只证明已请求启动，不是供应商已消费或成功完成。故障未知时不自动再次派发。

## 未知响应与过期恢复

- 模拟批准响应丢失：保留原请求身份，只做回读；普通 404/409、浏览器时钟到期不证明操作未生效。
- 初始代次 0 的提案过期时，重新明确确认关闭；只有数据库持久关闭标记才能将原批准判定为不会生效。
- 关闭响应丢失后再次回读；并发关闭只产生一次审计，不推进策略代次、不创建任务或运行。
- 已批准（包括随后停用）的提案不能改造成“未批准过期”；关闭标记不可撤销，不能依靠时钟回拨重新批准。
- 功能关闭或公司暂停时仍能有权限地读取、停用未来策略、关闭过期提案，但不得新增运行。

## 保留与回退

- 受控绑定保留任务/Agent/运行证据；物理删除绑定 Agent 应收到明确 409，不应是内部错误。正常未绑定 Agent 的原有删除规则不变。
- 优先使用归档/停用，不删除证据来绕过绑定。已授权组织删除的新 v2 依赖按绑定、当前头、回执、策略顺序清理。
- 旧版本不可变 DELETE 触发器仍有组织清理兼容债务；新 v2 顺序修复不等于所有历史组织均可完整删除。
- 停用只影响未来任务，不承诺取消已接纳运行、撤销已发生副作用或退费；功能回退不是数据库降级。

## 尚需用户环境验证

真实 Casdoor 会话、真实 CLI/模型/计费、全平台进程行为、真实浏览器布局与输入法、供应商送达/发布不由本清单或本地 C2 夹具证明。实际验证时记录版本、账号类型、环境、操作、结果与证据，不能仅凭安装或配置成功判定完成。

## 本地无费用链路回归入口

在仓库根目录、已安装项目依赖的 Node 24.11+ 环境运行：

```sh
pnpm exec vitest run --config tests/mimouse/private-prompt-vitest.config.ts \
  server/src/services/mimouse-private-prompt-tests/integration.test.ts \
  --maxWorkers=1 --no-file-parallelism
```

该夹具自行新建带所有权标记的临时 PostgreSQL 集群，执行历史检查点到当前迁移、私有固定集生产与中央费用结算、人工批准后的受控运行和负向检查。模型边界替换为无网络 Node 子进程，不使用真实 CLI 或账号；绝不把现有数据库目录传入夹具。结束时应看到 `shutdown verified pidFile=false processAlive=false`。具体测试数与通过状态以本次输出及 VERIFICATION 中冻结提交为准，不以本命令存在判定成功。
