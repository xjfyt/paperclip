## 本轮修复与证据边界

- `MarkdownEditor` 的富文本捕获键盘处理和故障回退 textarea，在原生事件 `isComposing=true` 或旧式 `keyCode=229` 时跳过应用提交、补全和导航逻辑。普通 Enter/Shift+Enter 不被新增代码拦截；非组合状态 Ctrl/Cmd+Enter 仍走原提交回调。
- `InlineEntitySelector` 搜索框在相同条件下不切换高亮、不选中、不推进下一项。组合 Escape 另在该选择器的 `onEscapeKeyDown` 取消 Radix 的提前关闭；它是局部弹层关闭保护，不是全局阻止组合按键。
- 两个现有组件测试套件共 **69 项通过**，新增 **6 项回归**在修复前全部失败、修复后通过；覆盖富文本/回退、组合 Enter/Shift/Ctrl/Cmd+Enter、旧式 229、补全和选择器的 Enter/Tab/方向/Escape、组合结束后正常提交/选择。测试是 jsdom 合成事件，富文本编辑器使用现有 mock，**不代表真实系统输入法或 Lexical 编辑链路通过**。
- 三项 token 静态检查通过。未运行完整类型检查、构建、浏览器、数据库或外部网络测试；本轮按资源约束仅做限定组件测试和静态检查。`pnpm check:token-gates` 包装命令触发的依赖自动检查在本地目录创建失败后停止，改为下列直接 Node 命令，没有完成安装。

## 真实系统输入法：全部待人工验收

请使用隔离测试组织、虚构任务、无自动执行的测试 Agent；记录操作系统、浏览器版本、输入法名称/版本和实际页面。复制粘贴中文、自动化直接填值、合成 `isComposing`/229 事件都不能代替以下验收。

| 环境 | 中文拼音 | 日语假名/罗马字转换 | 当前状态 |
|---|---|---|---|
| Windows + Chrome/Edge | Microsoft 拼音（或实际使用的输入法） | Microsoft 日语 IME | 未测试 |
| macOS + Safari | 系统拼音 | 系统日语输入法 | 未测试 |
| macOS + Chrome | 系统拼音 | 系统日语输入法 | 未测试 |

逐项对中文和日语执行；候选尚未确认时必须看得到系统候选窗或组合下划线。

- [ ] **IME-01 富文本提交**：在新建任务/评论编辑器输入中文“测试任务”和日语“テスト課題”。组合中分别按 Enter、Shift+Enter、Ctrl+Enter（Windows）/Cmd+Enter（macOS）。应用不得创建任务、发送评论或清空草稿；系统输入法自行确认候选。组合结束后再按普通 Enter/Shift+Enter，保持该编辑器原有换行行为；再按 Ctrl/Cmd+Enter，只提交一次，正文完整。
- [ ] **IME-02 提及/命令补全**：打开 `@` 提及或 `/` 命令菜单，再输入未确认的中文/日语组合。分别用方向键、Enter、Tab、Escape 操作输入法候选；应用不得提前插入提及/命令或切换自己的候选高亮。确认组合并重新键入普通补全快捷键，验证提及 Enter/Tab 可用；技能命令仍遵循原有“先导航再 Enter”规则，不新增自动选择。
- [ ] **IME-03 内联选择器**：在任务的负责人/项目等搜索选择器中输入中文/日语。组合中的 Enter/Tab 不选中、不调用下一步、不关闭弹层；方向键不移动应用高亮；Escape 取消系统组合时应用弹层仍在。确认组合后普通方向键+Enter 或 Tab 选中一次，普通 Escape 关闭。清空查询、关闭重开后重复一次。
- [ ] **IME-04 回退 textarea**：在开发/隔离测试夹具中通过受控富文本解析错误进入标有 `MDE-*` 的原始文本回退，不修改生产数据或强造不可恢复正文。重复 IME-01；草稿不得丢失。若无法获得回退夹具，记录“阻塞：无受控回退入口”，不可把富文本通过当作回退通过。
- [ ] **IME-05 组合边界**：特别在 Safari 重复“候选确认后紧接着 Enter”的时序，检查是否因 `isComposing` 已结束而误提交（代码兼容 `keyCode=229`）。再用英文键盘重复正常提交/选择与取消，确认没有遗留的组合锁定。

每次实际发送/创建后核对任务或评论数量；遇到疑似重复发送先检查状态，不盲目再发。任何失败记录具体表面、按键时序、期望/实际、截图或脱敏录屏；不要记录凭据或真实敏感正文。
