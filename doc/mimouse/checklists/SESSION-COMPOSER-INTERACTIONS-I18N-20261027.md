- 服务端错误、用户标签/答案/理由、任务/会话/附件ID、URL、命令、文件名和密钥字节保持原义；不把原文识别成翻译键。日志继续遵守既有脱敏规则，不能为了“原文保留”关闭脱敏。
- 换语不能新增写入、上传、重发或鉴权请求；检查读请求时与既有轮询/成功后缓存刷新区分，不把正常生命周期请求误算成换语副作用。

## SESSION：Agent 运行详情、日志与密钥

1. 展开运行详情的会话区，检查登录入口/pending、会话变更标记、Before/After 和日志三类标题四语；原会话ID、命令、登录URL、stdout/stderr/JSON 正文保持原样，原展开状态不重置。
2. 假登录请求保持 pending 时换语：仍禁用，只发一次原 agent/company 请求；非 `Error` 显示本地回退，`Error.message` 保留原文。返回虚构结果后检查命令、URL和输出，不实际执行/访问认证流程。
3. 用0/1/多任务夹具检查清会话：0个时不出现入口；1个与多个确认框符合本语言数量规则。取消确认不请求；假确认只清原来触及的任务集合，pending 换语不重发、不增删任务ID，失败后可正常继续操作。
4. 在密钥页输入名称草稿，生成假 token 后显隐并连续换语：title/aria 本地化，名称草稿、token、显隐状态不被重置；显隐不是新建密钥，不额外请求。假复制值须逐字一致，不能把遮罩串当成真实值。

## INTERACTIONS：六类实际任务交互回调

1. 在任务详情依次检查接受、拒绝、回答、批量判定、取消、跳过；确认/复选确认/建议任务分别使用正确反馈。pending 未结束不能提前报成功，成功后展示返回状态；跳过成功维持现有无 toast 规则。
2. 接受草稿与应用判定分别测试0/1/多项；接受同时记录 skipped 数，判定区分全部完成与部分完成，不能把0项说成1项或把部分完成说成全部完成。英文/西语单复数独立核对，中文/日语不能机械照搬英文后缀。
3. 拒绝标签只翻译“选择了…”等系统包装；自定义标签按既有 trim 规则保留文字，空标签走本地回退。理由、答案、判定内容、选项顺序、交互ID与幂等身份不因换语改写。
4. 六种操作各模拟 `Error("Submit failed")`、带 `{{keep}}`/`<tag>` 的原始错误及非 `Error` 对象：仅后者用本地回退，不渲染隐藏字段或解释成 HTML；Promise 拒绝保持可由实际调用方接住，不新增未处理拒绝。
5. 请求未完成时切语再返回，新 toast 用完成时语言；随后换语，已有 toast 不追溯改写。换语本身不调用第二次交互操作，失败不把既有成功缓存倒退或自动重放。
