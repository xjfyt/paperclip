# 本地产物清单界面与手工验收

## 范围

编码交付页现在提供“记录本地产物清单”，调用既有
`POST /api/companies/:companyId/coding/:id/artifacts`，未修改后端权限或合同。
输入为固定 `headSha`、1–100 字符版本和 1–30 个文件；每个文件只提交
`path / platform / arch / buildJob`。平台为 windows/macos/linux，架构为
x86_64/arm64，路径最多1000字符，声明的构建任务最多200字符。

这不是浏览器上传或构建按钮。服务器读取交付所关联、允许访问的 active
local_fs 工作区内的真实文件并计算大小与 SHA-256；服务端核对工作区、分支、
干净 Git HEAD 和固定提交，拒绝目录、工作区外真实路径和哈希期间变化的文件。
界面额外拒绝绝对路径、盘符、`.` / `..` 路径段，不尝试代替真实路径验证。
符号链接即使看似相对，也由服务器检查解析后的目标是否仍在工作区内。

保存**替换**清单并使旧固定提交审阅失效，且按现有配置可能排队发送
`coding.artifact_ready` 通知；确认文案明确这两项已有副作用。没有新调用 review、
push、Runner、签名、上传或部署 API。返回的测试状态仍为 not_run，签名仍为
unknown；现有六目标矩阵仍展示未核验，不升级发布资格。

## 未知结果与身份边界

此 POST **没有幂等键或 compare-and-swap 版本合同**。界面没有自动重试；双击
只发一次，发送期间不可重复确认。网络错误、5xx、非匹配回执都显示未知。
发送前在 sessionStorage 写入公司/用户/session/交付/SHA限定的随机操作token，
不保存文件路径、正文或凭据。成功、明确拒绝和人工核对后的清理都先比较token归属；
卸载后的迟到响应不清理存储，不会抹掉后来操作的未知保护。
刷新、关闭重开和当前标签页导航
不能直接清除此标记。存储不可用则阻断新的发送。

未知后仅提供只读刷新，不能凭“有清单”或“清单一样”证明本次 POST 成功。
人类核对已存清单和活动记录并解决未知结果后，可显式准备另一项**新操作**；
该动作清空草稿及确认，不重发旧请求。浏览器清除存储、新标签页或另一个客户端
不共享这个保护，仍需操作者对账，前端不是服务端恰好一次保证。

明确400/401/403/404/409/422拒绝不自动重试。失权清除草稿与写控件；其他拒绝
须重新核对并确认。公司、用户、同用户session、交付或SHA变动重建界面；旧请求
迟到响应不会填入新身份或触发新身份刷新。成功后的读取失败独立提示，不将已确认
写入误标为失败而鼓励重复提交。当前接口没有防止两位管理员并发覆盖的CAS，
本切片不声称解决；多人操作应先协调。

私有交付列表和代码差异不使用全局URL-only GET合并池，改为独立
`requestResponse/readApiJson`、AbortSignal和no-store。查询身份同时绑定session与
认证复核时点；认证正在复核时隐藏旧私有操作，复核后必须有新的列表读取。差异
读取亦独立取消/隔离，旧session审阅POST的迟到回调不能关闭新界面或刷新新身份。
这不取消已被服务端接受的写入，也不改变后端允许的local_trusted Board权限。

## 用户手测（全部默认未执行）

使用可丢弃测试公司与工作区。先保持通知worker关闭，除非已明确授权测试目标。
真实会话权限、文件字节、操作系统路径行为、长文本布局不由jsdom替代。

| 编号 | 操作 | 预期 |
| --- | --- | --- |
| AM1 | 四语打开入口，填版本和已有工作区相对文件；进入核对但取消 | 无POST、无哈希、无通知、旧审阅不变化；重开需重新勾选 |
| AM2 | 正确SHA、干净工作区，明确确认 | 只发一次POST；服务端文件SHA-256/大小与独立计算一致；现有矩阵更新但全部目标仍未核验 |
| AM3 | 确认现有审阅与通知配置的影响 | 成功保存使旧审阅失效，需重新审阅新清单；通知关闭时不发送；开启情况只在授权测试目标验证 |
| AM4 | 缺文件、目录、逃逸符号链接、绝对路径、..、不匹配HEAD、脏工作区 | UI或服务端拒绝，无伪成功；界面没有放行或自动修正路径功能 |
| AM5 | 哈希时更改文件；实际大文件等待 | 若后端检测变化则拒绝；等待中不能重复提交；超时/断网不宣称没有写入 |
| AM6 | 后端写入后丢弃HTTP响应，再刷新页面 | 显示未知，只有只读刷新；不自动POST。核对清单/活动后才可明确准备新操作 |
| AM7 | 连续双击、取消重开、同用户重新登录、公司切换、旧请求晚到 | 双击一次POST；确认不继承；旧内容/结果不进入新身份 |
| AM8 | 普通成员/Agent/其他公司/不可读私有任务，或发送前撤权 | 后端拒绝；无越权文件哈希；失权时草稿与写控件清除 |
| AM9 | 关闭sessionStorage权限，或清空后重新进入未知操作 | 存储不可用时不发送；人工清空存储不能当作操作未发生，须核对活动记录 |
| AM10 | 两位管理员同时记录不同清单 | 记录接口无CAS的现有限制；以最后服务器结果对账，不宣称前端可防并发覆盖 |
| AM11 | A请求未回→离开→返回核对未知→明确新建B→A迟到→刷新 | A不能删除B操作token，B仍显示未知；B没有自动重试 |
| AM12 | 保留旧会话的慢列表/差异读取，然后切换或复核会话 | 旧操作隐藏，旧读取取消；新会话独立请求，不接受旧响应或沿用确认；local_trusted合法读取仍可用 |

## 本切片自动检查

纯 React/jsdom 和注入 API 回执测试验证合同字段、四语键/占位符、确认、相对路径、
30项限制、重复点击、读取失败、未知回执持久标记、拒绝/失权及身份切换。
不读取真实工作区文件，不运行数据库、服务器、模型、外部API或构建。
类型检查、生成locales、最终集成构建由主工作树统一运行；不得将定向检查记作全量通过。
