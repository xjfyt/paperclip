# 0358：反馈人工验证与受控提示词应用表

## 适用范围

0358_chunky_shockwave.sql 是由集中 Drizzle schema 生成、按依赖顺序整理的增量迁移。新增反馈人工验证表，以及提示词应用提案、目标 head、配置/回退回执、派发回执四表。不自动创建应用绑定、不调用模型、不发送通知，不将人工声明升级为机器验证。

生成后保留此前全部 journal 项与历史 snapshot。原生成顺序把复合外键放在目标唯一键之前，中央改为：新表 → 唯一约束/索引 → 外键。没有修改此前已发布 SQL，也不增加迁移器的非事务例外。

## 运维边界

- 这是维护窗口迁移，不承诺零停机。先备份并验证恢复方法，停止应用与所有写入 worker，等待旧事务退出，再迁移。
- heartbeat_runs、mimouse_coding_deliveries、mimouse_feedback_promotions 的新复合唯一键需要扫描既有数据并获取锁。已有主键保证身份唯一，但不能免除扫描和锁成本。
- 单事务应用；lock_timeout=5s、statement_timeout=120s 是每条语句限制，不是整个维护窗口或迁移 advisory lock 的总时限。
- 超时/异常必须停止上线并保留错误，不删除 journal、锁文件或强行认定已完成。不静默切换为非事务并发索引。
- 真实大库副本的迁移时长、磁盘/WAL、写事务排空与恢复演练仍需用户环境实测。空库夹具不代表生产升级性能。
- 不提供删除新表的自动 down 命令。回退必须协调应用版本与完整备份；若新版本已有业务写入，先停写并处理新增记录/未知外发台账，不能直接恢复旧备份导致丢记录或重放。

## 约束目的

- 反馈回执必须引用同公司、同反馈晋级任务、同任务的两份编码交付。每公司 requestId 唯一；允许同反馈多份不可变历史声明，不视为当前发布成功。
- 提示词提案固定公司/Agent/revision；目标 head 与派发回执引用准确的应用回执代次，不允许跨公司或混用 Agent/run/issue。
- 派发记录区分 prepared 与 dispatched；后者要求持久时间与 prompt 哈希。数据库完整性不等同于供应商已消费输入或执行成功。
- 过期只控制待批准提案，已配置绑定是否可用由当前权限、环境/版本一致性及显式回退决定。
