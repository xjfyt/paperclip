# 首次使用：公司、Agent 与任务

> **对应代码** — `ui/src/App.tsx`、`ui/src/pages/Companies.tsx`、`ui/src/components/OnboardingWizard.tsx`、`ui/src/pages/NewAgent.tsx`、`ui/src/pages/IssueDetail.tsx`
> **维护提示** — 首次引导、组织创建、Agent 配置、任务入口或用户权限变化时更新
> **最后验证** — 2026-10-29（对照产品合同、页面与路由；不是本页全部步骤的浏览器通过记录）

## 一、进入正确实例

先按[开发入门](01-development.md)启动当前源码，或访问运维给出的实例地址。确认页面对应本仓版本及正确公司；上游 npm 包或镜像不会自动包含本仓二开。

| 部署状态 | 首次进入的操作 |
|---|---|
| 本机 `local_trusted` | 使用回环地址进入受信本地控制面，无人类登录流程 |
| 自托管 `authenticated/private` | 登录/注册实例账号；全新实例按界面完成首位管理员认领，认领完成前仅开放给可信人员 |
| 自托管 `authenticated/public` | 由运维提供 CLI 生成的首位管理员邀请；不支持私网实例的浏览器直接认领 |
| 已启用 Casdoor | 按实例展示的登录方式操作；SSO、WorkBuddy OAuth 和模型账号是不同授权 |

管理员初始化的精确条件见[部署模式](../../doc/DEPLOYMENT-MODES.md)。不要把 claim/invite URL、Cookie、token 或登录材料粘贴到问题报告。

## 二、创建公司并确认范围

通过组织入口的新建操作打开引导，填写公司名称及目标。公司创建与 Agent 创建分开：新公司允许零 Agent，仪表盘可访问；跳过、关闭或以后再配置，不应暗中创建 Agent 或启动任务。

1. 在新公司仪表盘确认当前公司名称与上下文。
2. 填写或补充公司的目标，再按需要建立项目和工作区；工作区必须是你允许 Agent 操作的目录。
3. 如暂时只查看功能，可保留零 Agent。准备执行时再明确配置 Agent。
4. 调整成员和权限时使用公司访问管理；实例管理员、公司成员、Agent key 和个人偏好具有不同作用。

公司边界以服务端授权为准。部分托管环境限制一实例一公司，UI 会收起不允许的新建入口；不能据此推断自托管也只有一个公司。

## 三、配置第一个 Agent

在 Agent 新建入口或显式引导中选择执行适配器，填写名称、角色、模型、工作目录和运行配置。先看对应适配器合同，确认运行时已安装、账号可用、凭据引用及允许的工作区范围。

| 配置 | 核对内容 |
|---|---|
| 角色与组织 | CEO/工程/研究等职责、报告关系；不是通过名称获得额外权限 |
| 运行时与模型 | 本地 CLI、网关、HTTP、外部包或原生 runner 的实际要求；模型 ID 保持原标识 |
| 凭据 | 个人或公司连接是否允许当前责任用户/Agent 使用；选中已保存连接不保证它仍有效 |
| 工作区 | 路径、仓库、权限和隔离策略；避免将不相关私人目录作为执行范围 |
| 预算与心跳 | 金额、触发条件和并发；保存后先确认何时会实际执行 |

连接检测和环境测试可能访问供应商，应按实际适配器说明理解其副作用。配置成功、测试环境成功、真实业务任务完成分别记录。Qoder/WorkBuddy 的本仓外部包安装入口与限制见[集成边界](../04-modules/01-integration-boundaries.md)。

## 四、创建一项可验收任务

从任务创建入口填写目的、明确输入、允许范围、预期成果和验收方法。选择公司内单一 assignee，关联项目/工作区及必要的父任务；指定 Agent 可能触发真实执行，先核对账号、费用和执行范围。

推荐首项任务使用合成数据和可丢弃工作区，要求一个小且能直接检查的成果。不要把真实通知、生产记账、推送/合并或部署当作默认连通性测试。若仅验证界面，可创建不指派 Agent 的合成任务，并保持不执行。

在任务详情检查计划/评论、运行状态、文件和成果、费用以及待审批项。需要人类输入或审批时在对应交互卡处理；暂停与恢复也使用正式控制入口，不通过反复发“继续”绕过控制条件。

## 五、查看成果和处理失败

交付应能从任务中的文件、文档或工作成果打开。工作区引用依赖该工作区仍可访问；需要跨环境交付的文件应按[产物合同](../../doc/AGENT-ARTIFACTS.md)保存可检查附件。

发生错误时保留任务/运行标识、当前版本、时间及脱敏诊断。网络未知、等待审批、暂停和失败不是同一状态；不要对未知外部操作重复创建或重发。按[故障排查](../05-maintenance/03-troubleshooting.md)定位，再看对应功能合同的恢复步骤。

二开逐项手测见[用户验收](../../doc/mimouse/USER-ACCEPTANCE.md)。本页是使用指导，不是这些旅程已全部执行通过的报告。
