# 文档维护与分层验证

> **对应代码** — `package.json`、`scripts/check-project-docs.mjs`、`scripts/check-project-docs.test.mjs`、`docs/docs.json`、`doc/mimouse/`
> **维护提示** — 文档工具、检查范围、导航或证据维护方式变化时更新
> **最后验证** — 2026-10-29（入口与本仓文档结构核对）

## 一、维护目标

让读者从总入口找到当前合同、执行方法和可信证据。采用[文档编写规范](../00-doc-rules.md)的编号、标题、维护信息和事实源层级；格式检查只是第一层，不代表命令执行过或功能可用。

本仓已存在大量上游文档和二开历史记录，先修正能影响操作的事实，再按触达主题收束重复说明。不要为了目录整齐搬动全部页面或重写产品规格。

## 二、每次改动的步骤

代码和文档共同维护同一事实，按以下顺序核对：

1. 按源码路径确定 owner，查看[规范触发表](../00-doc-rules.md#六代码变更触发表)列出的合同。
2. 核对参数、默认开关、权限、调用路径、数据去向和失败/未知行为；发现冲突记录具体源码与合同依据。
3. 更新稳定主题正文、对应代码路径、维护提示和“最后验证”范围；总导航只更新入口。
4. 行为变化同步用户验收、相关回归与剩余项；一次执行的日志、失败重跑和 SHA 留在证据页。
5. 检查新改文件的本地链接、锚点、标题、代码块语言和维护字段；涉及站点发布时检查 `docs/docs.json` 导航及对应页面。
6. 按改动运行必要验证，记录真实结果；文档未执行的命令写明仅完成源码核对。

## 三、检查分层与结论

每一层有独立证据和局限，不能相互替代。

| 层次 | 检查内容 | 局限 |
|---|---|---|
| 路径与格式 | 文件存在、相对链接、锚点、编号/标题、维护信息、代码块语言 | 链接可达不代表描述正确 |
| 源码与合同 | 命令来自 `package.json`、参数来自 parser、默认值与权限来自实际 owner | 源码核对不等于运行成功 |
| 可执行验证 | 对应类型、测试、构建、页面渲染与操作结果 | 本地夹具不等于真实供应商/用户验收 |
| 真实环境/最终包 | 明确版本、OS/架构、租户和 artifact 的业务 oracle | 只覆盖指定范围，不能顺延到未来输入 |

本仓提供原生 Node 的有界检查入口，命令如下：

```sh
pnpm docs:check
node --test scripts/check-project-docs.test.mjs
```

检查范围固定为根 `README.md`、`docs/README.md`、`docs/00-doc-rules.md` 和 `docs/01-overview/`、`docs/02-getting-started/`、`docs/03-config/`、`docs/04-modules/`、`docs/05-maintenance/` 中的正式 Markdown。检查编号文件/目录命名、唯一 H1、编号 H2/H3、维护提示/验证日期以及仓库相对链接的文件与锚点，忽略 fenced code 示例。根 README 只豁免维护元数据要求。中文锚点保留，重复标题后缀和显式 HTML 锚点均按目标解析；缺失文件或锚点使命令非零退出。

既有上游文档仅在成为链接目标时核对路径/锚点，不检查其全文规范，也不访问外部 URL。该命令不证明链接页面的事实、代码行为、站点渲染、真实环境或最终发行包通过。旁仓 MiWork 的检查实现没有直接搬入，本仓以自己的 `package.json` 和脚本为准。

## 四、处理现有文档债务

当前编号中文文档与既有文档共存，按主题推进，不新建重复 Wiki。

| 已识别情况 | 维护方式 |
|---|---|
| 根入口的上游归属与二开安装范围 | 中文根入口指向本仓源码、合同和验收；保留上游与许可证归属，不把公开上游包当本仓部署物 |
| 功能合同首段堆叠历史 SHA 和测试总数 | 新入口不复制这些数字；后续按主题将稳定行为与日期证据分离，保留证据原文和回链 |
| “当前”“已通过”未绑定输入 | 补齐明确日期、完整 SHA、输入摘要和验证范围；历史记录不倒写为新树通过 |
| 环境受阻被视为永久能力限制 | 写明当次 OS/环境和可重试条件；在新环境重新运行，不直接继承旧 blocked |
| 只有旧环境临时日志路径 | 补可检查 artifact 或明确证据不可用；不可仅根据报告数字重建通过事实 |
| 旧合同和新实现冲突 | 对照 owner、产品合同及消费者，修复最小事实差异并留回归；不要同时维护两份支持表 |
| 英文 Mintlify 与中文 Markdown 入口不同 | 分别核对导航；`pnpm docs:dev` 只能证明其实际纳入页面的站点行为 |

## 五、改动交付记录

交付说明列出调整文件、修正事实、检查命令及结果、未逐页检查区域和下一步具体范围。仅整理入口时不宣称完成全仓文档审计；仅验证本地 API 时不宣称浏览器已验收。功能完成标准继续遵循 [AGENTS](../../AGENTS.md)及[验证规范](01-verification.md)。
